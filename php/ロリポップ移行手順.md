# ロリポップへの引っ越し手順（初心者向け）

> 画面の名前や場所は、ロリポップの更新で少し変わることがあります。見つからない時は、近い名前の項目を探してください。
> この作業の間も、いまの Render 版（https://zaiko-sg.onrender.com）は、そのまま使えます。**切り替えるまで、何も止まりません。**

## 全体の流れ

1. ロリポップの準備（PHPの版・データベース・FTP・公開フォルダ）
2. GitHub に、ロリポップの接続情報を預ける（Secrets）
3. 自動アップロードを動かす（GitHub Actions）
4. `config.php` を置く（データベースの接続情報）
5. データを入れる（phpMyAdmin）
6. 動作確認
7. 切り替えの日にやること

メモ用に、先に次の表を作っておくと楽です（**パスワードは、紙やパスワード管理アプリに。このチャットや GitHub のコードには書かない**）。

| 項目 | 自分の値 |
|---|---|
| FTPサーバー | |
| FTPユーザー | |
| FTPパスワード | （ここには書かない） |
| データベースのサーバー名 | |
| データベース名 | |
| データベースのユーザー名 | |
| データベースのパスワード | （ここには書かない） |
| 公開するURL | |

## 1. ロリポップの準備

### 1-1. PHPのバージョンを選ぶ
1. ロリポップの「ユーザー専用ページ」にログインする。
2. 左のメニューから「サーバーの管理・設定」→「**PHP設定**」を開く。
3. PHPのバージョンを **8.2 か 8.3** にする（8.1以上が必要。いちばん新しい安定版でよい）。

### 1-2. データベース（MySQL）を作る
1. 「サーバーの管理・設定」→「**データベース**」を開く。
2. 「作成」を押して、次を決める。
   - データベース名: 好きな名前（例: `zaiko`）。ロリポップが前にアカウント名を付けることがある。
   - ユーザー名: 自動で決まる場合はそのまま。
   - パスワード: 自分で決める（長く、他と同じにしない）。
   - 文字コード: **UTF-8（utf8mb4があればそちら）**。
3. 作り終わると、一覧に「**サーバー名**」「データベース名」「ユーザー名」が出る。表にメモする。
   - 「サーバー名」は、`mysqlXXXX.phy.lolipop.lan` のような名前。これを `config.php` に書く。

### 1-3. FTPの情報を確認する
1. 「サーバーの管理・設定」→「**ロリポップ！FTP**」または「FTP・Web作成」を開く。
2. 「FTPサーバー名」「アカウント(ユーザー名)」を表にメモする。パスワードは、ロリポップの契約時のものか、FTPアカウントで決めたもの（忘れたら、その画面で再設定できる）。
3. 注意: 自動アップロードは、**FTPS（暗号化されたFTP）** で送ります。ロリポップはこれに対応しています。つながらない時は、後ろの「困った時」を見てください。

### 1-4. 公開するフォルダを決める
このアプリは、`public` という名前のフォルダの中だけを、インターネットに公開する作りです（設定ファイルなどを、外から見られないようにするため）。

1. ロリポップの FTP（「ロリポップ！FTP」の画面でもよい）で入って、一番上のフォルダに `zaiko` という名前のフォルダを作る。
2. 「サーバーの管理・設定」→「**独自ドメイン設定**」を開く。
3. 使うドメイン（または、新しく作るサブドメイン。例: `zaiko.自分のドメイン`）を選び、**公開（アップロード）フォルダ**を `zaiko/public` にする。
   - 独自ドメインがなければ、ロリポップが用意する無料のサブドメインでもよい。
4. 同じ画面か「**独自SSL証明書導入**」で、そのドメインの **SSL（https）** を有効にする。**https でないと、iPad のホーム画面アプリや、写真・共有の機能が動かないことがあります。**

> まだ `zaiko/public` というフォルダは空でかまいません（次の「3」で、自動で作られます）。

---

## 2. GitHub に接続情報を預ける（Secrets）

パスワードを、プログラムの中に書かないための仕組みです。預けた値は、あとから**見ることはできません**（上書きだけできます）。

1. ブラウザで、GitHub の自分のリポジトリを開く（https://github.com/inoinomata-sys/zaiko）。
2. 上の「**Settings**」→ 左の「**Secrets and variables**」→「**Actions**」を開く。
3. 「**New repository secret**」を押して、次の4つを、1つずつ登録する。

| Name（名前。この通りに） | Secret（中身） |
|---|---|
| `LOLIPOP_FTP_SERVER` | FTPサーバー名（例: `ftp.lolipop.jp`） |
| `LOLIPOP_FTP_USER` | FTPのユーザー名 |
| `LOLIPOP_FTP_PASSWORD` | FTPのパスワード |
| `LOLIPOP_FTP_DIR` | `/zaiko/`（**最初と最後に `/`**） |

4. もう1つ、あると便利なもの（なくても動く）:

| Name | Secret |
|---|---|
| `LOLIPOP_SITE_URL` | 公開するURL（例: `https://zaiko.自分のドメイン`）。アップロード後に、自動で動作確認をする |

5. FTPS でつながらない時だけ、同じ画面の「**Variables**」タブで「New repository variable」から、
   `LOLIPOP_FTP_PROTOCOL` = `ftp` を登録する（暗号化なしになるため、最後の手段）。

> SSH のパスワードは、いまの仕組みでは**使いません**。将来 SSH を使う作業を足す時は、`LOLIPOP_SSH_USER` / `LOLIPOP_SSH_PASSWORD` という名前で、同じように Secrets に預けます（コードには書かない）。

## 2.5 自動アップロードの設定ファイルを置く（1回だけ）

私（Claude）のアクセス権限では、「自動で動くプログラム（ワークフロー）」を GitHub に置けないため、ここだけ、あなたの手で置きます。**コピーして貼るだけです。**

1. GitHub で、このリポジトリの `php/ci/lolipop.yml` を開く（https://github.com/inoinomata-sys/zaiko/blob/main/php/ci/lolipop.yml）。
2. 右上の「**Raw**」を押す → 全部を選んでコピーする（Mac: `Command + A`、`Command + C`）。
3. リポジトリのトップに戻り、「**Add file**」→「**Create new file**」を押す。
4. 上の名前の欄に、次をそのまま入力する（`/` を打つとフォルダになる）。

   `.github/workflows/lolipop.yml`

5. 下の大きな欄に、手順2でコピーしたものを貼る（`Command + V`）。
6. 右上の緑の「**Commit changes...**」→ もう一度「**Commit changes**」を押す。

→ これで、「Actions」に「ロリポップ版（PHP）の確認と自動アップロード」が出ます。**接続情報（2.）が入っていなくても、確認の自動テストだけは動きます。**

---

## 3. 自動アップロードを動かす

1. GitHub のリポジトリで、上の「**Actions**」を開く。
2. 左の「**ロリポップ版（PHP）の確認と自動アップロード**」を選ぶ。
3. 右の「**Run workflow**」→ 緑の「Run workflow」を押す。
   - 最初は、「**アップロードの予行演習**」にチェックを入れて動かすと安心（実際には送らず、送る内容だけ確かめる）。
4. 緑のチェックが出るまで待つ（**最初は10〜20分**。次からは変わった分だけなので数分）。
   - 途中で、本物の MySQL を使って、全部の画面・PDF・計算を自動で試します。**ここで失敗したら、アップロードされません**（壊れた版が公開されない仕組みです）。
5. 赤い×が出たら、その実行を開いて、「注釈（Annotations）」に出る文を、そのまま私（Claude）に貼ってください。直します。

これ以降は、**GitHub に push するたびに、自動でロリポップが最新になります**（`php/`・`templates/`・`static/` を変えた時）。

---

## 4. config.php を置く（データベースの接続情報）

`config.php` は、データベースのパスワードが入るので、**GitHub には載せず、ロリポップに直接置きます**。自動アップロードでは、上書きも消去もされません。

1. このリポジトリの `php/config.sample.php` を、自分のパソコンにコピーして、名前を `config.php` にする。
2. 中身を、表にメモした値に書き換える。

```php
<?php
return [
    'db_host' => 'mysqlXXXX.phy.lolipop.lan',   // 1-2 の「サーバー名」
    'db_name' => 'LAA0000000-zaiko',            // データベース名
    'db_user' => 'LAA0000000',                  // ユーザー名
    'db_pass' => 'パスワード',
    'debug'   => false,
];
```

3. ロリポップの FTP（ブラウザの「ロリポップ！FTP」でよい）で、`zaiko` フォルダの直下（`public` と同じ階層）に、`config.php` をアップロードする。
   - `zaiko/public/` の中ではなく、**1つ上**です。
4. パソコンに残った `config.php` は、使い終わったら消す（パスワードが入っているため）。

---

## 5. データを入れる（phpMyAdmin）

先に、手元でデータを書き出します（いまの Render 側のデータを MySQL 用に変えたもの）。

```bash
python3 php/tools/export_pg_to_mysql.py
```

→ `backups/mysql_data_日付.sql` ができます（個人情報が入るので、GitHub には載せません）。

1. ロリポップの「データベース」画面で、作ったデータベースの「**phpMyAdminを開く**」を押す。
2. 左で、作ったデータベースを選ぶ。
3. 上の「**インポート**」→「ファイルを選択」で、`php/sql/schema.mysql.sql` を選び、下の「実行」を押す。（**表の作成。先にこちら**）
4. もう一度「インポート」で、`backups/mysql_data_日付.sql` を選び、「実行」を押す。（**データの投入**）
5. 左に、表（products、stock、orders…）が並び、中身が入っていれば成功。

> 試しに入れて、やり直したい時は、もう一度 4 を実行すれば、データが入れ直されます（入れる前に、各表を空にする作りです）。

---

## 6. 動作確認

1. ブラウザで、`https://（公開するURL）/health` を開く。次のような文字が出れば、つながっています。
   - `"db": true`（データベースにつながっている）
   - `"font": true`（PDFの日本語フォントがある）
   - `"counts"` に、商品の数などが出ている（Render 側と同じ数）
2. `https://（公開するURL）/` を開く。在庫の画面が出る。
3. 次を、iPad で順に確かめる（Render 版と見比べる）。
   - 在庫: ＋／－、数を直接入力、確認
   - 使用入力: ＋／－
   - 発注: 画面を開く→数を入れる→確定→PDF（**最初のPDFだけ、10秒ほど時間がかかることがあります**。2回目からは速い）
   - お客様注文: 価格表から選ぶ→注文用紙（A5）のPDF→印刷
   - 設定: 商品マスター、担当者、発注の取り消し
4. **確認用のデータは、本番とは別物です。** ここで入力した内容は、切り替えの日に、いったん消して入れ直します。

---

## 7. 切り替えの日にやること

1. スタッフに、「○時から、入力しないでください」と伝える（5分ほど）。
2. 手元で、もう一度データを書き出す（`python3 php/tools/export_pg_to_mysql.py`）。
3. phpMyAdmin で、「5」の手順 4 を、もう一度行う（最新のデータに入れ直される）。
4. `/health` の `counts` が、Render 側と同じ数かを確かめる。
5. スタッフに、新しいURLを伝える。iPad・iPhone は、**ホーム画面のアイコンを入れ直す**（共有ボタン→「ホーム画面に追加」）。
6. **Render 側では、もう入力しない**（データが二つに分かれるため）。Render の「zaiko-sg」は、しばらく残しておけば、困った時に戻れます（戻す時は、ロリポップ側で入力した分を、Render に入れ直す作業が要ります）。

## 困った時は

| 症状 | 確かめること |
|---|---|
| Actions の自動アップロードが赤い | 「注釈（Annotations）」の文を、そのまま Claude に貼る |
| FTP につながらない | Secrets の名前・値（特に `LOLIPOP_FTP_DIR` の前後の `/`）。それでもだめなら、Variables に `LOLIPOP_FTP_PROTOCOL` = `ftp` |
| 画面が真っ白／「vendor が見つかりません」 | 自動アップロードが、最後まで終わっていない。Actions を確認 |
| 「config.php に db_host がありません」 | `config.php` が、`zaiko` の直下にあるか（`public` の中ではない） |
| `/health` で `"db": false` | `config.php` の接続情報。`db_error` の文を見る |
| `/health` で `"font": false` | アップロードが途中。Actions をもう一度動かす |
| PDF が出ない（エラー） | `config.php` の `'debug' => true` にして、画面に出る文を Claude に貼る。終わったら `false` に戻す |
| どこかの画面でエラー | データベースの `error_log` 表に、エラーが残っています（phpMyAdmin で開ける） |
| 変更したのに反映されない | ブラウザを、いったん閉じて開き直す。ホーム画面アプリは、いったん終了して開く |

## リポジトリを非公開にする時の注意

いまの GitHub のリポジトリは「公開」です（Render が、公開のリポジトリから読み込む設定のため）。**Render をやめて、ロリポップだけにした後なら、非公開（Private）にできます。** Render を使っている間に非公開にすると、Render の更新が止まります。

## 安全のために（おすすめ）

- ロリポップの「**アクセス制限**」（Basic認証）を、`zaiko/public` に設定すると、URLを知っている人だけが入れます。いまの Render 版には、パスワードがありません。iPad は、一度入力すれば、覚えてくれます。
- データベースのパスワードは、定期的に変える（変えたら、`config.php` も直す）。
